# AI 麻将决策辅助系统

**Mahjong AI Decision Assistant**

通过分析自己的手牌、各家的出牌和牌桌上的公开信息，推荐当前更优的出牌选择，并解释为什么应该打这张牌。

项目首先面向**四川麻将**：从手动录入牌局、获得出牌建议开始，逐步研究搜索、机器学习、深度学习和强化学习方法，提升决策质量。后续再加入图像识别，并探索对大众麻将等其他规则的支持。

> 当前状态：已实现四川麻将手动录入前端与规则听牌分析。完整规则裁决、计分、推荐算法、训练模型和识图尚未接入；下文的AI决策能力为研发目标。

## 当前可运行界面

前端位于 `ui/`，采用 React + Vite。打开页面后会显示带有明确标识的演示牌局，可通过“手牌设置”开始自己的牌局。

- 四家牌桌：自己的手牌与新摸牌分开展示；其他三家暗手只显示平放的牌背。
- 原创27种万、条、筒牌面；碰牌及明杠全部亮出，暗杠亮一张、其余三张为牌背。
- 选择四家中的庄家，录入自己的13张或庄家14张手牌、各家定缺；保存后从庄家出牌开始。
- 右上角显示剩余牌墙，起手发牌后55张；摸牌、杠后补牌每次减1，撤销恢复。别家普通出牌前未单独记录摸牌时，只补计一次，不重复扣数。
- 碰杠转移对应来源弃牌，校验每种已知牌最多4张；错误录入不会改变牌局，撤销可完整恢复上一步。
- 出牌后自动选择下一家：上家→我→下家→对家；选择自己默认摸牌，摸牌后切到出牌，碰杠后仍由操作玩家继续录入。撤销同时恢复录入座位和操作。
- 摸牌后锁定当前玩家，完成出牌或自摸胡前不能切到别家；碰后出牌、杠后补牌也保持锁定。补杠和暗杠须先记录摸牌。
- 自己出牌后，剩余手牌按万、条、筒及1—9自动排序；上下家的13张暗手会完整显示，碰杠后按实际暗手数量调整。
- 实时显示听牌，包括普通四面子一对将、七对、龙七对和金钩钓结构；校验定缺、副露、花色和四张上限。持有14张牌时，点选手牌可预览打出后听什么牌。
- 每张待牌显示已知信息下的未见张数；包含对手暗手，并非牌墙剩余张数。已见完的待牌单独标记。
- 别家摸牌无需输入未知牌面：新增一张分开的牌背，出牌后移除；可记录自摸、点炮胡和同一弃牌的一炮多响。
- 别家当前弃牌至少可胡、碰或明杠一项时才显示响应栏，全不可用时隐藏；支持直接响应和“过”。碰、明杠和点炮胡自动绑定当前弃牌及来源，不再选牌；自己的自摸直接使用新摸牌。
- 定缺花色禁止碰、明杠、补杠、暗杠、自摸胡和点炮胡。持有定缺牌时碰杠非定缺牌的未确定边界不标为已确认合法。
- 每位胡家的胡牌张亮在原“新摸牌”位置并标“胡牌”；自己的其余手牌保持正面，其他三家的暗手继续隐藏。别家自摸胡需选出实际胡牌张。一炮多响在各家手牌旁分别展示，同一实体牌只计数一次。
- 庄家合法起手14张可直接记录天胡，不额外摸牌或扣牌墙；起手输入的第14张单独放在旁边，重新打开设置仍保留它。普通第一轮摸牌成胡也会显示绿色自摸提示。
- 自己合法自摸时显示绿色提示栏，直接胡新摸牌；胡牌后提示消失，撤销可恢复。对局结束时，顶部中央显示“对局结束”。碰牌、明杠、补杠、暗杠均为直接按钮。
- 胡牌者保留暗手牌背并退出后续动作，自动选座跳过他；从本次逆时针最后一位胡牌者的下一位未胡玩家接续，三家已胡后结束。撤销可恢复胡牌、摸牌和结束状态。
- 查看规则摘要、下载规则文档；桌面与窄屏均可操作，窄屏手牌可横向滚动。

界面目前不推荐出牌、不显示虚构的AI概率或分数；自己的胡牌会校验定缺与手牌结构，别家的暗手未知，需按实际牌局录入。已限制放过的同牌胡机会至自己下次摸牌，碰杠解除过手胡等未确定边界尚未裁决。抢杠裁决、牌墙耗尽后的终局结算和番数结算尚未实现。牌局仅保留在当前页面，刷新会回到演示局。

### 本地运行

先安装 [Node.js](https://nodejs.org/) 22.12 或更高版本（包含 npm，建议使用 LTS 版本）。Windows、macOS 和 Linux 均可运行，不需要安装 Codex 或 pnpm。

克隆或下载仓库后，在仓库根目录打开终端：

```sh
cd ui
npm ci
npm start
```

打开 `http://127.0.0.1:4173/`。保持终端打开，按 Ctrl+C 停止。首次运行需要联网安装依赖；之后直接运行 `npm start`。如果代码更新后依赖发生变化，再执行一次 `npm ci`。

Windows 也可以双击 `ui/start.cmd`：首次启动会自动执行 `npm ci`，随后启动页面。启动器优先使用系统 Node.js；本机已有 Codex 自带 Node.js 时，也保留兼容支持。

默认端口为 4173。若同一端口已有本项目在运行，会直接显示访问地址；若端口被其他程序占用，可运行 `npm start -- 4174`，Windows 启动器可用 `.\start.cmd 4174`。

需要 Vite 热更新开发服务时，在 `ui` 目录运行 `npm run dev`，使用终端实际显示的地址。

生产构建及测试（同样在 `ui` 目录运行）：

```sh
npm run build
npm test
```

构建会输出 `dist/client/` 及模板所需的 `dist/server/`、`dist/.openai/hosting.json`。状态逻辑位于 `ui/src/game/state.js`；设计与操作验收记录位于 `ui/design-qa.md`。

## 项目目标

本项目希望回答三个问题：

1. **现在应该打哪张牌？** 根据当前已知信息，对合法出牌进行比较和排序。
2. **为什么推荐这张牌？** 解释它对手牌效率、胡牌速度、牌型收益和放炮风险的影响。
3. **其他打法有什么代价？** 展示备选出牌，让用户理解进攻、做大牌和防守之间的取舍。

核心追求是：**在尽量早胡、尽量胡大牌的同时，降低给其他玩家放炮的风险，提高长期对局的期望净得分。**

这几个目标可能冲突。例如，保留大牌路线可能降低进张效率；最快听牌的出牌可能更危险；为了避免高额放炮，有时需要放弃当前进攻。系统应根据局面和规则权衡，而不是始终只追求最快听牌、最高番数或最低风险。

麻将存在隐藏信息和随机摸牌。“最优决策”在本项目中指**在已知信息、指定规则和当前模型假设下，估计收益更高的合法决策**。系统无法知道对手的真实手牌或未来牌墙顺序，建议也不保证每局获胜。

## 首版范围：手动输入的四川麻将出牌助手

第一阶段先打通“录入牌局 → 分析局面 → 推荐出牌 → 解释理由”的流程。

### 输入哪些信息

- 自己的起始手牌、每次摸到的牌，以及自己的出牌。
- 各家按时间顺序打出的牌，以及公开的碰、杠和胡牌事件。
- 各家的定缺信息、当前行动玩家、仍在参与的玩家，以及可获取的剩余牌墙张数。
- 本局规则配置；需要考虑比分时，录入各家当前分数与已发生的结算。

其他玩家暗手和摸牌的具体牌面属于未知信息，不要求用户录入，也不能作为决策依据。事件记录应保留出牌顺序和牌的来源，避免碰杠后的同一张牌被重复计数。

### 输出哪些建议

- 当前最推荐打出的牌，以及其他主要候选牌的排序。
- 每种打法对向听数、有效进张和后续听牌机会的影响。
- 可争取的牌型路线及其在当前规则下的计分依据。
- 对各家放炮风险和潜在损失的估计，以及相关不确定性。
- 推荐理由、备选打法的取舍，以及尚缺少的牌局信息。

“向听数”用于衡量距离听牌还有多少步；“有效进张”指摸到后能改善手牌的牌。未见牌数量不等于牌墙中的实际剩余数量，因为其中还包含对手的暗手。

首版可以先输出规则和牌效率分析；只有建立并验证了相应模型后，才展示胡牌概率、放炮概率和期望收益等数值。启发式评分不能直接标成真实概率。

### 使用流程

1. 选择四川麻将规则配置，录入自己的手牌和已知桌面信息。
2. 每次记录摸牌、出牌、碰杠或胡牌事件，更新局面。
3. 轮到自己出牌时，系统检查输入是否合法，并比较所有合法候选出牌。
4. 查看推荐和解释，自行选择打法，再继续记录牌局。
5. 保存牌局用于复盘、算法比较和后续数据积累。

首版以出牌建议为中心。换三张、定缺、碰杠、是否胡牌等决策建议将在规则与评估能力稳定后逐步扩展；首版仍需记录这些事件，以保持局面正确。

## 四川麻将规则与计分

四川麻将的地方玩法和平台规则存在差异，需要确定一个明确、可复现的首版规则配置。**当前采用项目《麻将规则.md》的四川血战配置，以用户指定的百度百科条目为依据；尚未确定的叠加、封顶和特殊结算边界保留待确认。**

| 规则项 | 需要明确的内容 |
| --- | --- |
| 牌集与基础动作 | 使用哪些牌，摸打流程，允许的碰杠动作与胡牌条件 |
| 对局模式 | 血战到底、血流成河或其他模式；胡牌后是否继续参与 |
| 换三张与定缺 | 是否启用、执行顺序，以及定缺对出牌和胡牌的限制 |
| 牌型与番数 | 支持哪些牌型、各自番数、叠加方式及封顶规则 |
| 胡牌结算 | 自摸与点炮的支付方式，一炮多响如何处理 |
| 杠相关规则 | 杠分、补牌、抢杠胡、杠上花、杠上炮等的处理 |
| 流局与终局结算 | 查叫、查花猪、退税等是否启用及其计算方式 |

规则判断和计分应由可验证的规则引擎完成，作为所有算法共同使用的基础。训练、模拟、复盘和实际推荐必须使用相同的规则版本。

后续的“大众麻将”也需要先明确具体玩法，不能默认它等同于国标麻将或日式立直麻将。扩展时应增加独立规则配置，并重新验证策略与计分。

## 决策方法与研发思路

采用逐步迭代的路线：**规则与牌效率基线 → 不完全信息模拟与搜索 → 数据驱动模型 → 自博弈强化学习**。具体模型和技术栈根据实验结果确定。

| 方法 | 计划解决的问题 |
| --- | --- |
| 规则与组合分析 | 校验合法动作，判断胡牌与牌型，计算向听数和有效进张，建立可解释基线 |
| 概率建模与蒙特卡洛模拟 | 在符合公开信息的隐藏牌分布假设下，比较不同出牌的后续结果 |
| 搜索方法 | 研究信息集搜索等适用于不完全信息局面的方法，并评估收益与计算成本 |
| 监督学习与模仿学习 | 从适配规则的牌谱或模拟数据学习出牌偏好、局面价值及风险特征 |
| 深度学习与强化学习 | 训练策略网络、价值网络和对手风险模型，通过自博弈优化长期得分 |
| 大语言模型 | 辅助把结构化分析结果转成易懂的解释，支持交互与复盘 |

决策目标可以概念性地写为：

```text
推荐动作 = 在所有合法动作中，选择预计本局最终净得分最高的动作
```

最终净得分应计入当前规则下的胡牌收益、放炮损失、杠分和终局结算等因素。胡牌速度与大牌潜力会影响这些结果，而不是简单把“速度、番数、风险”三个数相加。早期启发式权重只是近似，需要通过对局评估逐步校准。

建议将系统分为输入与状态管理、规则与计分、手牌分析、决策评估、解释与复盘、训练与评测几个模块，使不同算法可以在同一规则和数据接口下比较。

训练和评估时，决策模型只能获得行动玩家在当时可见的信息。模拟器可以维护完整牌局，但不得把对手暗手或未来摸牌顺序泄漏到实际推荐输入中。

### 如何解释推荐

解释应来自算法实际计算的结果：例如某个候选保留了更多有效进张、放弃了哪条大牌路线，或为什么当前需要提高防守优先级。

大语言模型可以负责组织语言，但牌数、合法动作、番数和概率等事实应由对应模块提供。没有算出的指标不应编造；缺少关键信息时，应明确说明建议的适用条件。

## 学习已有开源项目

计划先研究已有仓库的规则组织、状态编码、训练流程、搜索和复盘方法，再根据四川麻将需求开展适配与改进。以下是已核对项目首页的初步参考，**尚未完成代码、模型效果和规则兼容性评估**。

| 参考项目 | 项目方向与计划研究内容 |
| --- | --- |
| [RLCard](https://github.com/datamllab/rlcard) | 包含麻将环境的牌类强化学习工具包；研究环境接口、智能体训练与评测组织方式 |
| [Mortal](https://github.com/Equim-chan/Mortal) | 面向日式立直麻将的深度强化学习 AI；研究策略学习和工程组织方式 |
| [mjai-reviewer](https://github.com/Equim-chan/mjai-reviewer) | 使用兼容 mjai 的麻将 AI 进行牌谱复盘；研究候选动作比较与分析结果展示 |
| [Chinese-Standard-Mahjong](https://github.com/ailab-pku/Chinese-Standard-Mahjong) | 国标麻将竞赛项目；研究规则相关实现与竞赛交互方式 |
| [sceneun1ty/mahjong-ai](https://github.com/sceneun1ty/mahjong-ai) | 自述面向川麻血战到底的识图与出牌分析助手；作为功能设计参考，效果需单独验证 |

日麻、国标和四川麻将的规则、计分与策略目标不同，参考项目的环境和模型不能默认直接适用。“开发更好的项目”应体现为在明确的四川麻将规则下，获得更好的对局得分、决策解释和使用体验，并以实验结果证明。

采用外部代码、模型或数据前，应核对对应许可证、使用条件和来源，并保留必要的署名。

## 开发路线

以下为完整研发路线；已完成手动录入前端与基础牌数校验，其余分析、计分和训练能力尚待实现。

| 阶段 | 主要工作 | 阶段成果 |
| --- | --- | --- |
| 1. 规则与局面基础 | 明确首版川麻规则；实现牌表示、事件记录、合法性检查、胡牌和计分 | 可重放、可校验的牌局状态与规则引擎 |
| 2. 手动输入 MVP | 实现手动录入、牌效率分析、候选出牌排序和解释 | 可使用的基础出牌助手 |
| 3. 攻防评估 | 加入隐藏牌采样、模拟、风险分析和收益比较 | 同时考虑速度、牌型价值和放炮损失的推荐 |
| 4. 学习与自博弈 | 建立数据集、训练环境、监督学习和强化学习实验 | 能与规则基线进行公平对比的策略模型 |
| 5. 图像识别与交互 | 识别手牌、弃牌和公开副露；支持人工校正、状态更新和复盘 | 减少手动录入成本的辅助系统 |
| 6. 规则扩展 | 明确大众麻将的目标玩法，扩展规则与计分，重新训练或适配模型 | 支持更多麻将规则的决策助手 |

图像识别结果应先经过人工校正和牌数校验，再进入决策模块，避免识别错误被当作真实牌局。

## 如何判断项目是否有进步

- **规则正确性**：使用人工核对案例验证合法动作、胡牌、番数、结算和事件重放；拒绝牌数冲突等不合法输入。
- **策略效果**：在同一规则下，对比随机合法策略、牌效率基线和进攻防守基线，报告平均净得分、胡牌率、放炮率、平均胡牌收益及胡牌速度。
- **比较公平性**：轮换座位，使用足够的随机牌局及多种对手，报告样本量和统计不确定性；学习模型使用独立评测数据。
- **概率可靠性**：若输出胡牌或放炮概率，检验预测与实际结果是否一致；策略分数与概率分别展示。
- **解释可信度**：推荐理由应能追溯到规则、特征或模拟结果，并说明主要备选打法的代价。
- **使用体验**：记录单次决策耗时、录入成本，以及后续识别准确率和校正成本。

是否采用更复杂的模型，取决于它是否在这些指标上带来实际改进。
